pi-ticketing

Tickets, todos, and delegation for pi — three capabilities pi does not ship, as one package. One SQLite file. Every session, every repo.

What it is

Tickets — the cold, durable record

A ticket is an immutable record with an append-only comment stream; status is the only field that ever changes. Nothing is ever deleted. The store is one SQLite file outside every repo (~/.pi/agent/ticketing/ticket.db, WAL mode, node:sqlite — zero runtime dependencies), shared by all sessions on all projects and worktrees; the autoincrement id is the only global ticket number.

Todos — the hot, ordered list

todo_write flushes the list wholesale; state lives in tool-result details, so it is automatically correct when you branch or fork a session. Each item backed by a ticket starts "N: …" — the ticket number is the item's permanent id, never renumbered. Closing item N: … mirrors ticket N's status automatically (fail-open: a broken store never breaks the flush).

Delegation — the hands

delegate spawns pi --mode json subagents with isolated context. The ticket number is the contract; the delegatee's first calls are ticket_get and ticket_rules. Its namespace is injected as TICKET_ROLLOUT_ID in the spawned environment — the same installed extension loads inside the subagent, so its writes land in the delegated namespace without trusting caller input.

The tools

ToolWhat it does
ticket_addCreate a ticket: one-line summary + the spec written ONCE (immutable body). Returns the permanent number N. Owner stamped from ground truth — never passed as input.
ticket_getRead one ticket: the row plus its comments, chronological. By number — no id needed.
ticket_listList tickets: yours by default, another session's by rollout_id (adoption), everything with all=true.
ticket_commentAppend ONE short go/no-go note (≤1000 chars). Long reports never go on the ticket.
ticket_statusThe ONLY mutation: set status. Owner-gated — takes the OWNING session's id.
ticket_rulesThe delegatee banner: immutability law, standing subagent rules, envelope recovery.
ticket_helpThe whole contract in one call — the recovery for a lost agent.
todo_writeFlush the hot list; mirrors statuses onto tickets; refuses delegatees (single writer, enforced).
delegateHand a ticket to a spawned pi subagent — single or parallel (up to 8).

Plus /tickets — a modal overlay listing the current session's tickets, grouped by status, Escape closes.

Identity

rollout_id IS the session id — one id, no other. Owners and comment authors are stamped from ground truth: the pi session id, or the delegated namespace injected into a subagent's environment — never taken from model input. Only two tools accept an id as input, deliberately: ticket_status (the owner gate) and ticket_list (cross-session adoption).

Errors

Every failure returns {code, message, corrected_call}. corrected_call is the COMPLETE call — received values kept, missing ones filled with real ids wherever they are derivable. Re-emit it verbatim (fill any <fill: …> placeholder) and the call succeeds. Type, enum, unknown-key, and length violations are rejected at the harness layer by TypeBox schemas before any handler runs.

Install

make install-repo DEST=<path/to/git-repo>   # project-local: DEST/.pi/
make install-global                          # every project: ~/.pi/agent/
make test                                    # 14 contract tests, no pi needed

The destination must be a directory containing .git (worktrees count). Never install both globally and project-locally — the installers refuse that combination, because pi would load both copies and crash on duplicate tool names.
